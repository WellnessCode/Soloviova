Репозиторій WellnessCode/Soloviova — набір Python-скриптів для маркетингу та керування проєктом Анни Соловйової, лікаря-дієтолога (проєкт Wellness-Код): AI-консультант з просування в Instagram, розсилка повідомлень лідам у Telegram і канал віддаленого виконання команд на сервері.

Три незалежні контури: консультації, розсилка, віддалене керування. Спільного стану між ними немає — лише спільний репозиторій.

Компоненти

AI-маркетолог

Бот

Telegram-бот, що працює як особистий консультант з Instagram-просування та персонального бренду лікаря. Спілкується українською чи російською — мовою співрозмовника, збирає контекст питаннями по одному й видає конкретні рекомендації: контент-план, оформлення профілю, рілси, залучення, монетизація.

Розсилка лідам

Разовий запуск

Скрипт повторного контакту: від імені особистого акаунта надсилає повідомлення людям, які колись лишали заявку на консультацію, але з якими не вдалося поспілкуватись. Працює обережно, щоб не потрапити під обмеження Telegram.

Виконавець команд

Демон на сервері

Канал керування сервером через GitHub: кожні 5 секунд перевіряє cmds/pending.json у репозиторії, виконує нову shell-команду (таймаут 120 с) і комітить результат у cmds/result.json. Дозволяє адмініструвати сервер без прямого SSH-доступу.

Файлcmd_runner_soloviova.py
Стекrequests · GitHub Contents API · subprocess
Протоколнова команда = новий id у pending.json; відповідь обрізається до 3000 символів
СередовищеGITHUB_TOKEN

Нотатки й ризики

Виконавець команд — це повний доступ до сервераКритично

Будь-хто з правом запису в репозиторій може закомітити довільну команду в cmds/pending.json, і сервер її виконає. Доступ до репозиторію варто тримати мінімальним, а токен — з найвужчими правами.

Персональні дані лідів зашиті в кодКритично

Список імен і Telegram-нікнеймів зберігається прямо в send_messages.py і потрапляє в історію git. Краще винести його в окремий файл поза репозиторієм (як уже зроблено з токенами через .env).

Історія діалогів бота не переживає рестартПомірно

Памʼять AI-маркетолога живе лише в процесі: після перезапуску бот забуває всі розмови. Якщо це заважає — додати збереження історії на диск або в базу.
